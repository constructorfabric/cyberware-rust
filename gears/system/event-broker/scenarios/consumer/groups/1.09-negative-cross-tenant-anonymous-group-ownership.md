# Cross-tenant access to an anonymous consumer group is denied

An anonymous consumer group is owned by the tenant that created it.  Any
operation performed by a different tenant on that group — `GET`, `DELETE`, or
subscribing to it (`POST /subscriptions`) — is rejected with `403 Permission
Denied`.  The group also does not appear in the listing of another tenant's
groups (`GET /consumer-groups`).

Named groups are explicitly excluded from this rule: they are platform
resources gated by an explicit `consume` permission grant, not by
tenant-equality.

## Ownership rules

| Operation | Anonymous group | Named group |
|---|---|---|
| `GET /consumer-groups/{id}` | 403 if caller tenant ≠ owner tenant | Allowed if caller has `:consume` grant |
| `DELETE /consumer-groups/{id}` | 403 if caller tenant ≠ owner tenant | Allowed if caller has `:manage` grant |
| `GET /consumer-groups` (list) | Excludes other tenants' groups | Included if caller has `:consume` grant |
| `POST /subscriptions` (JOIN) | 403 if caller tenant ≠ group owner tenant | Allowed if caller has `:consume` grant |

## Setup

- Tenant A creates an anonymous consumer group — owns it.
- Tenant B is a different tenant with a valid, authenticated identity.

## Scenarios

### 1. GET returns 403

```
GET /v1/consumer-groups/{group_id_owned_by_tenant_a}
Authorization: Bearer <tenant-b-token>

→ 403 Permission Denied
```

### 2. DELETE returns 403

```
DELETE /v1/consumer-groups/{group_id_owned_by_tenant_a}
Authorization: Bearer <tenant-b-token>

→ 403 Permission Denied
```

The group must not be removed — the denied DELETE is a no-op.

### 3. LIST excludes tenant A's group

```
GET /v1/consumer-groups
Authorization: Bearer <tenant-b-token>

→ 200 OK  { "items": [ ... ] }   # tenant A's groups absent
```

### 4. JOIN returns 403

```
POST /v1/subscriptions
Authorization: Bearer <tenant-b-token>
{ "consumer_group": "<group_id_owned_by_tenant_a>", ... }

→ 403 Permission Denied
```

