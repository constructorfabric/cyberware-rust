# Consumer resumes from a persisted cursor after reconnecting

A consumer reads from the earliest position, processes events up to some sequence N, and persists N as its last-processed cursor. When the consumer reconnects — whether after a crash, a graceful shutdown, or a rebalance eviction — it SEEKs to the integer N. The broker delivers from N+1 onwards, so no event is reprocessed and no event is skipped.

This is the positions-layer view of the Path A consumer pattern described in [flow-1.3](../flows/1.03-flow-path-a-consumer-with-db.md). It focuses narrowly on the SEEK call and its cursor semantics, not the full flow.

## Cursor semantics

The cursor is **exclusive**: seeking to N means "I have processed everything through N; give me N+1 next". A consumer that has never processed any event seeks to RF-1 (= 0 on a fresh topic), which makes the broker deliver from sequence 1 (the first retained event).

## Setup

- TOPIC_PREFILLED has 100 events with sequences 1-100 in partition 0.
- Consumer A subscribes to TOPIC_PREFILLED, SEEKs to "earliest" (cursor = RF-1 = 0), streams, and reads events until it receives sequence 40.
- Consumer A persists 40 to its local store and closes the connection.
- Consumer A creates a new subscription in the same group and SEEKs to the persisted integer 40.

## Request 1 — initial SEEK to earliest

```http
POST /v1/subscriptions/{sub_id}:seek HTTP/1.1
Content-Type: application/json

{ "partition_positions": [{ "topic": "...", "partition": 0, "value": "earliest" }] }

→ 200  [{ "topic": "...", "partition": 0, "value": 0 }]
```

Consumer streams, receives events with sequences 1-40, closes the connection.

## Request 2 — resume SEEK to persisted cursor

```http
POST /v1/subscriptions/{sub2_id}:seek HTTP/1.1
Content-Type: application/json

{ "partition_positions": [{ "topic": "...", "partition": 0, "value": 40 }] }

→ 200  [{ "topic": "...", "partition": 0, "value": 40 }]
```

## Expected first event on the resumed stream

The first `event` frame on the resumed stream carries `sequence: 41` — the event immediately after the persisted cursor.

## Side effects

- No event is reprocessed (sequence 40 is the cursor, not a delivered event).
- No event is skipped (sequence 41 is the first delivery on resume).
