# SEEK on an unknown subscription → 404 Not Found

Calling `:seek` with a `subscription_id` that does not exist returns `404 Not Found`. The broker has no cursor state for a subscription it does not know about.

## Setup

No prior state required. Use a random UUID as `sub_id`.

## Request

```http
POST /v1/subscriptions/{sub_id}:seek HTTP/1.1
Host: broker.example.com
Authorization: Bearer <tenant-token>
Content-Type: application/json

{
  "partition_positions": [
    { "topic": "gts.cf.core.events.topic.v1~acme.orders.v1", "partition": 0, "value": "earliest" }
  ]
}
```

## Expected response

- `404 Not Found` (`PD`)

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.not_found.v1~",
  "title": "Not Found",
  "status": 404,
  "detail": "subscription {sub_id} not found",
  "instance": "/v1/subscriptions/{sub_id}:seek",
  "trace_id": "<request-trace-id>",
  "context": {
    "resource_type": "gts.cf.core.events.subscription.v1~",
    "resource_name": "{sub_id}"
  }
}
```

## Side effects

None. The unknown subscription remains absent.
